# BitBoard implementation plan

## Projects

- `Tuck.BitBoard`: `netstandard2.1`, independent of the game and Unity.
- `Tuck.BitBoard.Tests`: `net10.0`, xUnit.

## Description

A shared tiled binary geometry library for computations throughout our projects. Support the functionality our existing code needs, using those call sites to guide the API rather than building a general-purpose collection of operations.

This implementation covers the library and its tests. Adapting existing projects to use it, adding their references, and updating mod packaging will happen later.

Each board uses one `ulong[]`: a packed dimensions header followed by row-major 8×8 tiles. Keep unused edge bits zero. Share operation implementations through read-only and writable spans: either board type can supply inputs, while mutation requires a mutable destination.

## Types

- `BitTile`: immutable 8×8 value backed by one `ulong`.
- `BitBoard`: immutable board with content equality and hashing.
- `BitBoardMut`: mutable board. Assignment shares storage; `Clone()` creates independent storage.

`BitBoard.ToMutable()` and `BitBoardMut.ToImmutable()` copy storage so mutable aliases cannot change an immutable board. Borrowing a read-only span does not copy storage.

## Operations

| Operations | Existing need |
|---|---|
| Create empty/filled rectangles; read cells/tiles; set/clear cells; clear/fill boards | `CellMask`, `CellBits`, inventory and placement construction |
| Count set bits; enumerate set-cell coordinates in deterministic row-major order | Shape area, capacity calculations, candidate offsets, boundary contacts |
| Quarter-turn rotation and horizontal reflection | Shape orientations and game-coordinate transforms |
| Test overlap and containment with signed relative offsets | Collision checks, inventory holes, placement fit |
| Union and subtraction into mutable destinations, with offsets | Occupancy updates, placement construction, search backtracking, shape merging |
| Complement within board bounds | Construct blocked cells from usable cells |
| Content equality and hashing, including dimensions | Shape caching and orientation deduplication |

Implement these with tile-level masks, shifts, and bitwise operations. Start with scalar word operations; add SIMD where measurements justify it.

Positions, game rules, and byte-valued cell/outside-bounds semantics belong in the eventual adapters. Value-specific masks can represent the binary parts of those computations.

## Tests

Compare operations against a simple cell-based reference. Cover partial tiles, tile boundaries, signed offsets, transforms, snapshot isolation, and equality/hash consistency.
